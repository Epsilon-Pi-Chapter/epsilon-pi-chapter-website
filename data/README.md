# Lineage Data Entry

This folder holds offline-editable spreadsheets used to fill in missing
biographical info for brothers in the chapter lineage on `script.js`.

## Files

- `lineage-data-entry.csv` — one row per member across every line in
  `lineageData` (generated by `scripts/generate-lineage-csv.js`).

## Workflow

1. Open `lineage-data-entry.csv` in Google Sheets or Excel.
2. Fill in the blank cells under `Major`, `Minor`, `Hometown`, and `LinkedIn`
   for any brother whose info is missing.
3. Leave rows for placeholder/memorial entries
   (e.g. `Dropped Dead and Gone`, `Eternally Remembered`) blank — they exist
   only so the row order matches `lineageData` exactly.
4. Export back to CSV (keep the same column order and header row) and share
   the file. A follow-up task will import the completed sheet back into
   `epsilon-pi-site/script.js`.

## Columns

| Column     | Editable? | Notes |
|------------|-----------|-------|
| `Line`     | No — join key | Season label, e.g. `Spring 2025`. Matches the top-level key in `lineageData`. |
| `Position` | No — join key | Line position, e.g. `1/Ace`, `11/Fly E11even - Tail`. |
| `LineName` | No — join key | The brother's line name (nickname). |
| `FullName` | No — join key | The brother's legal name. |
| `Major`    | Yes | Academic major. Leave blank if unknown. |
| `Minor`    | Yes | Academic minor. Leave blank if unknown. |
| `Hometown` | Yes | `City, ST` format (e.g. `Atlanta, GA`). |
| `LinkedIn` | Yes | Full profile URL (e.g. `https://www.linkedin.com/in/...`). |

> **Do not edit `Line`, `Position`, `LineName`, or `FullName`.** Those four
> columns are the join keys used by the import task to match each row back to
> the correct member in `lineageData`. Changing them will break the import.

## Regenerating the template

If `lineageData` in `script.js` changes (e.g. a new line is added), regenerate
the CSV from the project root:

```bash
node epsilon-pi-site/scripts/generate-lineage-csv.js
```

This overwrites `lineage-data-entry.csv` with the latest data, preserving any
values currently in `script.js`. Any unsaved manual edits to the CSV will be
lost, so merge before regenerating.
